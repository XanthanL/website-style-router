## 铁律 · 选型

1. **先定源，再谈设计。** 用户给的往往不是文案，而是 PDF / 图库 / 视频 / 一个 URL / 一句话。先把源变成可溯源的结构化数据（`source.md`），否则每条结论都是猜的。
2. **先定交付形态。** `standalone` 独立站 / `embedded` 嵌进已有站 / `system-only` 只出 token。形态不同，后半程全不同。
3. **先 Grill，再选型。** 意图不清就选型 = 凭空造需求。沿 `intake.md` 12 支决策树（B0–B11）走，一次一问、给推荐答案。
4. **先砍空间，再选风格。** 不许从 N 个风格里挑一个。菜单式选型必然向均值收敛 —— 这就是 AI 味的来源。用约束排除掉 80%，剩下的不是"选"出来的，是"剩"下来的。
5. **先定技术栈，再定风格与字体。** 技术栈决定「哪些风格做得出来、字体怎么加载」。先选风格再选栈 = 先承诺效果再发现实现不了，返工最贵。用 `scripts/pick_stack.py` 按需求（页数 / 交互 / 维护者 / 数据源 / 宿主 / 语言 / 渲染 / 性能）**先排除、再定序**，产出 `tech-stack.md` 并写 3 条可观测的证伪条件。**技术栈必须是被判断出来的，不是默认继承 Astro。**（[`techstack.md`](../techstack.md)）

6. **先选族，再选锚点。** 40 个锚点直接挑又退化成菜单。两级收敛：约束 → **族（11 选 1–2）** → 锚点 → 1 个 spec。族由「内容支撑力 / 转化目标 / 密度诉求」决定，**不由品类决定**（`styles/families.md`）。
7. **风格必须驱动布局，不能只驱动颜色。** 每个锚点声明 `layout` + `axis`。输出时套该原型的骨架，不是共享模板换色。
8. **图文策略是选型的一部分。** `imagePolicy` / `iconPolicy` 在 Grill 阶段就要确认。低质图不许用 → 换靠排版撑的锚点。
9. **只落 token，不落形容词。** "克制""高级感"不可执行。`--space-6: 64px`、`never: 居中正文` 才可执行。
10. **IA 优先于风格。** "由哪几页组成"比"长什么样"更决定成败。所有现成工具（TypeUI / Curio / uipro）都只管后者。
11. **风格库按需加载。** 40 锚点索引 → 1 个族 → 1 个锚点。禁止把 specs / signatures / fonts 全量读进上下文。

## 铁律 · 执行

12. **决策权分明。** 每个决定先归到 A 自主 / B 推断+确认 / C 必须问 / D 绝不代做（`decide.md`）。**判据：错了的返工成本 × 我有没有可靠依据。** 该问的没问 = 用户事后逐个指导；不该问的反复问 = 让用户填问卷。
13. **人必须在落定后点头。** 技术栈 + IA + 锚点 + 布局 + 中轴 + 字体 + 语言落定后停下确认。这是唯一的强制确认点。
14. **嵌入宿主 = 服从宿主。** 色板/字体/圆角/动效/顶栏/底栏/语言切换器一律对齐宿主，宿主令牌优先于本 skill 的锚点。**宿主技术栈也优先**（Phase 1.5 退化为确认）。新增数据用新模块、渲染做分支，**不破坏宿主已有实体**。
15. **提取与校验必须靠脚本。** 手抄 62 张图名 / 17 个作品必然出错（真实踩过：扩展名、年份、作品名各错一处）。用 `scripts/extract_source.py` + `scripts/verify_assets.py`。
16. **"引用对了 + 状态码 200"不能证明图片能显示。** 扩展名可能与真实编码不符（JP2 伪装 `.png` → Chrome 静默空框）。必须用 PIL 读真实 `format`。
17. **提取不了的，明说提取不了。** 本机若无 OCR / ASR（`check_env.py` 会告知）—— 扫描件与视频旁白要给明确降级方案，**不许假装**。
18. **每条内容必须能指回源。** 溯源格式 `p12 · "原句"` 或 `<url> #selector`。指不回去的就是编的，删掉；确实缺的进「待补」表 + `[待填]` 可见标记。
19. **字段定义了就必须渲染出来。** 数据里有 `images: [...]` 却只渲染第一张 → 交付不完整，而"引用校验"还会 PASS。
20. **中轴与尺寸在落定前定完。** 中轴（`left-rail`/`center-axis`/`split`）、区块去留（**Contact 默认不做**）、三档宽度。这几项返工最贵。
21. **交付时交代三件事**：我自主决定了什么 / 哪些是推断的（依据）/ 哪些还没确定。**说清边界比做得多更重要。**

## 铁律 · 落地与审美

22. **token 由脚本生成，不许手编。** 命中锚点后：有 spec 读 spec；无 spec 跑
    `python scripts/emit_tokens.py --anchor <slug>`。它按签名（字阶比 / 基准字号 / 行高 /
    容器宽 / 行长 / 栅格 / 字距 / 色相 / 彩度 / 色温 / 圆角 / 基调 / 动效）**确定性**展开，
    并经 WCAG 校验。**凭印象手写 token 必然向均值收敛** —— 这就是 AI 味的技术成因。
23. **字体必须是被搭配出来的，不是被继承的。** 每个锚点的标题 / 正文 / 等宽 / 中文回退由
    `styles/fonts.json` 指定（40 个锚点的 display 字体**全库唯一**），由 `emit_tokens.py`
    落成 `--font-display` / `--font-body` / `--font-mono` / `--font-cjk`。
    **禁止让 `--font-display` 的首族停在 `system-ui` / `-apple-system` / `Inter` 这类通用栈** ——
    那是「40 个站长得一样」最直接的技术成因。加载方式（自托管 / CDN / 系统回退）由 Phase 1.5
    选定的技术栈决定（`fonts.json` 的 `loading` 字段）。
24. **排版数值先于配色。** 页面的"好看"约 70% 在字阶 / 行高 / 行长 / 字距，配色是后半段。
    这三个数按 [`typography.md`](../typography.md) 的族带取值，**有据可依，不靠手感**。
25. **交付前必须跑审美数值审计。**
    `python scripts/audit_tokens.py <MASTER.md> --anchor <slug>`。**F 级不为 0 = 没做完。**
    判据与修法见 [`design-qa.md`](../design-qa.md)。`checklist.md`（流程形状）和它（数值审美 +
    字体搭配）是两道独立的门，都要过。
26. **一份真源。** 设计系统只能有一份生效的 token 文件（通常是 `src/styles/tokens.css`），
    `MASTER.md` 是它的可读副本。**两份值不一致就是漂移** —— 历史真实案例：`MASTER.md` 写
    `--accent: #B83232` 而站点实际是 `#B33A2A`，文档与实现各说各话。

## 铁律 · 反同质化（交付前逐条自检）

> 这一组是 v0.7 新增的，针对一个真实失败模式：产出「千篇一律、只是不同的 Markdown 组织器」。
> 只查数值与流程，不查**差异**，就会得到一批数值全过、观感全同的站。

27. **结构必须跟着锚点变，不是换色。** 每个产出必须声明 **≥3 条结构级视觉签名**（如：对角切分、
    悬挂标签、可见基线网格、非对称栏比、超尺寸数字），且每条都要能在渲染结果里指出来。
    `layouts.md` 给了每个布局原型的签名菜单与组合规则。
28. **字体搭配逐站不同。** 同一批交付里任意两个站的 `--font-display` 不得相同；同一站内
    标题与正文不得同字体。由 `audit_tokens.py` 的 **F6** 与 `validate_skill.py` 的 **F8** 机器校验。
29. **产物形状要能反映技术栈。** `plain-html` 的产物是 index.html + 样式表；`astro` 才是
    `src/pages/`。**不同需求的产物目录结构相同 = Phase 1.5 没做**，回退重做。
30. **单站自洽 ≠ 批次多样。** 每个站单独跑审计都能过（F 级 0），五个摆在一起仍可能塌 ——
    实测：5 个站 `--bg` **5/5 全是 `#FFFFFF`**、40 个锚点只用了 3 个、视觉签名 5/5 缺失。
    **开工前跑 `python scripts/ledger.py --check`，交付前跑
    `python scripts/audit_tokens.py --batch <批次目录>`。** 这两道是「跨站差异」这条腿，
    与「单站自洽」同等重要 —— 只查前者，必然得到一批数值全过、观感全同的站。
31. **底色是被选的，不是默认的。** `--surface` 七档（`white` / `paper` / `tint` / `stone` /
    `slate` / `ink` / `deep`）必须显式落定。**同一批次里同一档出现两次以上就要换。**
    深色站与有色底站不是特殊需求，是常规选项 —— v0.7 把底色明度写死在代码里，
    这两种站在架构上做不出来。
32. **同一锚点第二次使用必须换组合。** `--variant`（尺度变体轴）× `--pair`（族备用池字体）
    × `--surface`（底色档）三者的组合，让同一锚点在第二次使用时不再逐值相同。
    **原样复用同锚点 = 把同一个设计系统交付了两遍。**

## 铁律 · 可导航性（IA 的第二半）

> 这一组是 v0.9 新增的，针对另一个真实失败模式：**设计达标、功能不达标** ——
> 页面好看，但**只有单个 index**（条目再多也全塞进去、单条无法被分享），
> **长页只能一翻到底**（没有任何页内跳转）。审美判据全过，浏览体验照样不合格。

33. **页面粒度是被判断出来的，不是默认单页。** IA 只回答了「这一页由哪些区块组成」，
    没回答「内容该分成几页」—— 缺了后半句，所有站都会产出单个 `index`。
    用 `scripts/pick_pages.py` 按内容判据（`entries` 条目数 / `depth` 深度 /
    `shareable` 可否独立分享 / `indexable` 是否需被收录 / `themes` 并列主题数）
    算出 `single` / `master-detail` / `multi-page`，写进 `content-profile.md`。
    **「拆页」与「不拆页」都要有理由 —— 「没想过」不是理由。**
    **多页 ≠ 多份数据**：能静态生成时数据仍只有一份，多页不增加维护成本。
34. **页内导航跟着页面长度与阅读模式走，不是每个站都加。**
    短页加目录是噪音；**转化页加整页目录 = 请用户跳离说服链**。
    档位（`none` / `anchor-jump` / `sticky-toc` / `section-rail`）由 `blocks` 区块数、
    `lookup` 查阅型区块数、`linear` 是否线性阅读决定（[`architectures/granularity.md`](../architectures/granularity.md)）。
    **声明了导航就必须真的做出来，且每个 `href="#x"` 都要有对应的 `id="x"`** ——
    声明与产物是否一致由 `audit_tokens.py --site` 的 **F14 / F15** 机器校验。
