# IA：目录索引型（Directory）

**核心命题**："这儿有什么——而且它在变。"

## 适用条件
- 条目**频繁更新**（日更/周更）或**数量多**
- 用户是**回来查特定信息**的，不是第一次来的陌生人
- 需要"今天/当前"的状态可见
- 维护者非技术 → 必须单一数据源

## 区块组成
```
单页，顺序固定：
  01 当前状态（今天有什么 / 现在开着吗 / 最新一条）
  02 索引主体（表格或行列表，条目 = 一行）
  03 元信息（时间、地点、规则、FAQ）
```
**数据源必须是单一文件**（`src/data/*.json` 或 md 集合），页面只是渲染它。更新 = 改那一个文件。

行结构建议：`名称 | 关键属性 | 状态`。属性列要短，长描述折到展开或详情页。

## 典型误用
- 只有 3 个条目还做索引 → 表格比内容还重，改走 narrative
- 内容硬编码进组件 → 每次更新要改代码，非技术维护者必弃坑
- 加筛选/搜索但条目 <20 → 功能比内容重

## Token 倾向
- **等宽数字**（tabular-nums）用于价格、日期、数量——列对齐是这套的命
- 行分隔用 1px 细线，不用卡片、不用阴影
- 密度可以高，但行高必须 ≥1.5
- 状态用**文字标签**而非纯颜色（色盲 + 打印）

## 被排除的常见原因
条目少且不变 → 索引层是纯负担；需要被"感受"而非"查询" → 改走 narrative 或 portfolio。

## 页面粒度与页内导航（默认，可被内容推翻）

> 阈值与完整判据见 [`granularity.md`](granularity.md)。这里只给本原型的默认倾向。

- **默认粒度**：`single` —— 单页索引 + 单一数据源，这是它的立身之本
- **默认页内导航**：`none` —— 索引页是「扫一眼今天有什么」，加目录是噪音
- **判据**：条目 ≥12 **且**每条有独立深度内容（不只一行属性）→ 升为 `master-detail`
  （索引 + 条目详情）
- ⚠️ 升为 `master-detail` 后，**数据源仍必须是一份**（详情页从同一个 JSON 生成）。
  抄成两份 = 非技术维护者每次更新要改两个地方 —— 这是 directory 最怕的失效方式。
- 加筛选 / 搜索的判据不变：条目 <20 不加（功能比内容重）。
